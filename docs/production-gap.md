# Production gap

This working demo is not configured to accept real money or deliver real service credentials. The user completed reCAPTCHA and both authenticated interfaces were inspected read-only. Main merchant screens are reproduced, while actual source payment operations were deliberately not performed. The following work needs separate implementation and acceptance before a public customer launch.

| Priority | Work                                                       | Acceptance evidence                                                                                                                                                                   |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0       | Replace sandbox payment/top-up with a provider integration | Signed server-to-server webhooks; server-owned amount/currency; idempotent event processing; settlement reconciliation; no user-created real balance                                  |
| P0       | Choose deployment/data architecture                        | Cloudflare Worker + SQLite-backed Durable Objects is deployed. Production still needs permanent shop tenancy and cross-device identity instead of browser-scoped demonstration spaces |
| P0       | Extend managed secret storage for production               | Demo keys are already Cloudflare encrypted secrets. Add rotation, key versions, audited access, separate production keys and a successful restore drill                               |
| P0       | Production authentication                                  | HTTPS Secure cookies, verified email, reset/recovery, admin MFA, durable throttling, anti-bot/abuse protection and session lifecycle review                                           |
| P0       | Backups and disaster recovery                              | Encrypted consistent SQLite backup plus key protection, tested recovery, defined recovery targets; D1 equivalent if migrated                                                          |
| P1       | Payment and delivery lifecycle                             | Provider-pending/paid/processing states, retry queue, late payment after stock exhaustion, traceable refunds/reversals and customer support escalation                                |
| P1       | Privacy and shop policies                                  | Owner-approved terms, privacy notice, consent records, retention/deletion workflows, support contact configuration and ownership/rights of sellable goods                             |
| P1       | Security review                                            | Independent audit of all APIs; distributed limits; injection/XSS/CSRF/IDOR testing; dependency/security patch review; no real keys in bundles or logs                                 |
| P1       | Monitoring and operation                                   | Structured redacted logs, alerts, payment/stock reconciliation, failure tracing, uptime checks and support process                                                                    |
| P1       | Load and concurrency                                       | Multiple real clients/processes, large inventory imports, storage contention, latency targets, gateway retries and recovery under interrupted transactions                            |
| P2       | Product management breadth                                 | Multi-variant/category editor, promotions with usage/time rules, advanced variants, accessible media management and integration settings                                                               |
| P2       | Shopping breadth                                           | Multi-line cart, combined checkout, provider receipts/tax handling, review media/moderation and scheduled preorder fulfillment                           |
| P2       | Multi-store platform                                       | The `/stores` merchant-selector purpose is verified. Replace browser-scoped demo spaces with permanent organizations, tenant ownership and membership/invitation flows                |

The complete server flow is deployed to Cloudflare and tested through the online URL. Worker `astra`, its durable SQLite namespace, runtime secrets and the ASTRA Pages hostname serve this demonstration. No real payment account is connected. Keep browser isolation and TEST-only inventory until permanent merchant identity, gateway and operational controls are ready.
