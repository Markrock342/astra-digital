## หน้าร้านต่อบอร์ด

### UI-01 หน้าร้าน Desktop/Mobile

มี header, เมนูมือถือ, bottom nav, footer และ breakpoint ใน `src/styles.css` ธีมสว่าง/มืด/ตามระบบอยู่ที่ footer (`ThemeSwitch`) ไม่ได้อยู่บน header

ตอนรันจริง Desktop และจอ 390px เมนูเปิดได้ และไม่ล้นแนวนอน ยังไม่ได้ไล่ทุกหน้าบนแท็บเล็ต

### UI-02 เลือกดูและซื้อสินค้าพร้อมส่ง

Flow ที่ต่ออยู่: Home หรือ `/products` → รายละเอียด → ตะกร้าหรือ checkout → `POST /api/orders` → หน้าออเดอร์ → `POST /api/orders/:id/pay` ด้วย outcome sandbox

ตอนรันจริงเห็นชื่อ ราคา และรูปได้ แต่กดซื้อต่อไม่ได้เพราะ `POST` ตอบ 403

### UI-03 สินค้าหมด

การ์ดที่ Home ขึ้นป้าย `สินค้าหมด` เมื่อสต็อกรวมเป็น 0 หน้ารายละเอียดขึ้นคำว่าสินค้าหมดต่อตัวเลือก และปิดปุ่มเมื่อสต็อกเป็น 0

ตอนรันจริง เลือก «DISNEY+ 30 DAYS ยกแอค» แล้วปุ่มใส่ตะกร้ากับซื้อเลยถูกปิด ตัวเลือกที่ยังมีของยังโชว์จำนวนคงเหลือเป็นตัวเลข

### UI-04 Preorder และเลขคิว

สินค้า preorder มีป้าย `สั่งจอง` และปุ่ม `จองเลย` วันปิดรับจองกับวันได้รับของถูกเขียนตายใน JSX เป็น 15 พ.ย. และ 16 ธ.ค. ไม่ได้มาจาก API

หลังจ่าย sandbox สถานะเป็น `PREORDER` แต่หน้าออเดอร์ไม่แสดง `queueNumber` ทั้งที่ `orderDetail` ของ reservation ส่งฟิลด์นี้มา ประวัติการซื้อไม่มีชิปกรอง `PREORDER`

Admin มีแท็บสถานะ `ต้องจัดส่ง` แต่ `GET /api/admin` ไม่ได้เลือก `queue_number` และไม่มีหน้าเรียก `GET /api/queue`

### UI-05 ID/Password ของเจ้าของออเดอร์

ของที่ส่งจริงคือโค้ดในตาราง `inventory` ไม่ใช่คู่ ID/Password แยกฟิลด์ `orderDetail` ถอดรหัสให้เฉพาะเจ้าของเมื่อสถานะ `DELIVERED` staff ที่เปิดออเดอร์คนอื่นได้ `codes: []`

รอบรันจริงเข้าหน้านี้ไม่ได้เพราะล็อกอินไม่ได้

### UI-06 แจ้งเตือน โปรโมชั่น และฟอนต์

ประกาศร้านมาจาก settings และโชว์บน Home ไม่มีหน้า inbox แจ้งเตือน ทั้งที่มี `GET /api/notifications` แท็บ Admin `coupons` เป็นข้อความว่าง ไม่มี API โปรโมชั่น ฟอนต์ที่โหลดคือ Geist และ Noto Thai ไม่มีตัวเลือกฟอนต์ให้สลับ

## Admin

เมนูหลักใน `src/Stores.tsx`: ภาพรวม, สินค้า, ออเดอร์, การเงิน, ลูกค้า, ตั้งค่า เข้าได้เฉพาะ `role === "ADMIN"`

| แท็บ | ใช้กับ API เดิมได้ | หมายเหตุ |
|---|---|---|
| ภาพรวม, สินค้า, สต็อก, ออเดอร์, ลูกค้า, การเงิน, ตั้งค่าร้าน | ได้ | ผ่าน `GET /api/admin` และ POST settings/products/inventory |
| หมวดหมู่ | บางส่วน | นับจากสินค้าที่มี ไม่มี CRUD หมวด |
| รีวิว | ทางลัดไปหน้าร้าน | ไม่มีคิวกลั่นกรอง |
| คูปอง, สแตมป์, เช่าไอดี, แจ้งปัญหา, OTP | เปลือกเมนู | ข้อความว่ายังไม่มีรายการ อยู่นอก scope รอบนี้ |
| ตั้งค่าจัดส่ง, เช่า, LINE, OTP, ทีม, โดเมน, แพ็กเกจ | เปลือกเมนู | ไม่นับเป็นงานที่ต้องทำให้ครบ |
| แชท, คิว preorder, แจ้งเตือน | ไม่มีเมนู | API มีบางส่วนแล้ว |

รอบรันจริงหน้า `/admin` เด้งไปเข้าสู่ระบบ ปุ่มทดลองเป็นเจ้าของร้านได้ 403

## ความใกล้เคียง Reference

`docs/reference-analysis.md` บันทึกว่าหน้าร้านปัจจุบันตั้งใจใช้โครงแบบเว็บต้นทาง: พื้นหลังโทน `#0a0a0a`, คอนเทนต์กลางราว 1104px, ฟอนต์ Geist, hero แบบคำลอยและเส้น grid, สินค้าตัวอย่างโทนสตรีมมิ่ง, หลังบ้านเป็นแถบเมนูแนวนอน

QA-03 ยังไม่ผ่านจนกว่าจะมีโครงนำทาง ลำดับชั้น และภาพลักษณ์ใหม่ที่ Mark เทียบแล้วเห็นว่าเป็นของ FIFACORP

## สิ่งที่เปิดดูได้ในรอบรันจริง

- Desktop และจอ 390px: เมนูหน้าร้านเปิดได้ ไม่ล้นแนวนอน
- สินค้า DISNEY+ ตัวเลือกสต็อก 0 ขึ้นคำว่าสินค้าหมด และปิดปุ่มใส่ตะกร้ากับซื้อเลย
- MONOMAX มีป้ายสั่งจอง วัน 15 พ.ย. / 16 ธ.ค. เป็นข้อความในหน้า ไม่มีเลขคิว
- ไม่มีปุ่มแชททั้งหน้าร้านและทางเข้า Admin
- ล็อกอิน ซื้อของ และเข้า Admin ทำไม่จบ เพราะ `POST` ตอบ 403

## Blocker ก่อนลงมือออกแบบทั้งระบบ

0. Blocker B1 ใน `API_GAPS.md`: `POST` ผ่าน Vite ใช้ไม่ได้ ห้ามถือว่า flow ซื้อของ เข้า Admin หรือแชทผ่านแล้ว
1. Mark ต้องรับทราบว่ารอบ redesign คือการออกจากโครง Reference ไม่ใช่เปลี่ยนสีบนโครงเดิม
2. Brand สี โลโก้ และชุดฟอนต์ที่ลูกค้าอนุมัติยังไม่มี ถ้ายังไม่มา จะใช้ temporary token
3. เลขคิว preorder มีใน API รายละเอียด reservation และ `GET /api/queue` แต่ UI Admin ที่ใช้อยู่ไม่ได้รับเลขคิว
4. รูปแบบ credential ที่ลูกค้าต้องเห็น (โค้ดบรรทัดเดียว หรือ ID + Password) ยังไม่ถูกยืนยันใน payload ปัจจุบัน
5. โปรโมชั่นและตัวเลือกฟอนต์ไม่มีของให้ต่อ ถ้าไม่อยู่ใน scope ที่ตกลงแล้ว UI-06 จะเหลือแค่ประกาศร้าน ธีมสี และกล่องแจ้งเตือน
