# หลังบ้าน ASIA EXTRA — Audit และ Functional Requirements

วันที่: 11 พ.ย. 2026 · ผู้ตรวจ: มาร์ค · ผู้รับงานหลัก: น็อต (DB/API) · UI: แบงค์
อ้างอิงขอบเขต: [SOW-FIFACORP-FINAL-20261110](../prompts/SOW-FIFACORP-FINAL-20261110.md)

ป้ายในเอกสาร
- **[SOW]** อยู่ในใบเสนอราคาแล้ว ต้องมีก่อนส่งงาน
- **[ยืนยัน]** จำเป็นต่อการเปิดร้านจริง แต่ SOW ไม่ได้เขียนชัด มาร์คต้องยืนยันกับลูกค้าว่าอยู่ในราคาเดิมหรือไม่
- **[เพิ่ม]** นอก SOW ต้องตกลงราคาก่อนทำ
- **N** = งานน็อต (ตาราง, API, ทดสอบ) · **B** = งานแบงค์ (หน้าจอ)

## 1. ผล audit: สิ่งที่หลังบ้านเป็นตอนนี้

### 1.1 เมนูที่ยังเป็นเดโม (มีชื่อ แต่ไม่มีระบบ)

| เมนู | สภาพตอนนี้ | ควรทำ |
|---|---|---|
| ออเดอร์ › เช่าไอดี | หน้าว่าง "ยังไม่มีรายการในร้านทดลองนี้" | **เอาออก** ร้านไม่มีบริการเช่า |
| ออเดอร์ › แจ้งปัญหา | หน้าว่าง | **เอาออก** ระบบทิกเก็ตเคลมอยู่นอก SOW |
| ออเดอร์ › รับ OTP | หน้าว่าง | **เอาออก** |
| สินค้า › หมวดหมู่ | แสดงหมวดที่ฝังในโค้ด (`server/catalog.mjs`) แก้ไม่ได้ | ทำ CRUD (FR-P5) |
| สินค้า › โค้ดส่วนลด, บัตรสะสมแสตมป์ | หน้าว่าง | **ซ่อน** นอก SOW |
| สินค้า › รีวิว | มีแค่ปุ่มลิงก์ไปหน้าร้าน | ทำหน้าจัดการรีวิว (FR-P8) หรือซ่อน |
| ตั้งค่า › หน้าร้าน / รับเงิน / จัดส่ง / เช่าไอดี / บอท LINE / บัญชีรับรหัส / ทีมงาน / โดเมน / แพ็กเกจ | **ทุกแท็บแสดงฟอร์มเดียวกับ "ร้าน"** | เหลือเฉพาะแท็บที่มีระบบจริง (FR-S) |
| คู่มือร้านค้า | ข้อความ "เติมโค้ดทดลอง" | เขียนใหม่สำหรับร้านจริง |

### 1.2 ฟีเจอร์ใน SOW ที่มี API แล้ว แต่ไม่มีหน้าจอเลย

| ฟีเจอร์ (SOW) | API ที่มี | หน้าจอ |
|---|---|---|
| แชทในเว็บ | `/api/chat/threads`, `.../messages`, `.../close` | **ไม่มีทั้งหน้าร้านและหลังบ้าน** |
| รายงานอันดับผู้ซื้อ วัน/สัปดาห์/เดือน/ทั้งหมด | `/api/rankings/buyers?period=` | **ไม่มี** |
| แจ้งเตือนในเว็บ | `/api/notifications`, `.../read` | **ไม่มี** |
| ช่องทางจ่ายหนึ่งวิธี | `/api/admin/payment-channel` | **ไม่มี** (ตั้งค่า › รับเงิน เป็นฟอร์มร้าน) |
| ออเดอร์สำหรับพนักงาน (แบ่งหน้า) | `/api/staff/orders?cursor=` | ไม่ได้ใช้ หลังบ้านโหลดทุกออเดอร์จาก `/api/admin` |

สามข้อแรกเป็นของที่ต้องส่งตามใบเสนอราคา ต้องเร่งก่อน

### 1.3 ลูกค้า

- ตารางมีแค่ ชื่อ / สถานะ / ยอดเงิน / สมัครเมื่อ
- **ช่อง "สถานะ" เขียนตายตัวว่า "ปกติ"** เพราะตาราง `users` ยังไม่มีสถานะ และแบนไม่ได้
- ยอดเงินคำนวณในเบราว์เซอร์จาก ledger ทั้งร้าน ซึ่งเป็นเครดิตทดลอง (`DEMO_CREDIT`)
- กดเข้าไปดูรายละเอียดลูกค้าไม่ได้
- แก้ชื่อ อีเมล หรือรหัสผ่านไม่ได้ และบังคับออกจากระบบไม่ได้
- ตาราง `users` มีแค่ `name` ช่องเดียว ไม่มีชื่อกับนามสกุลแยก
- ปุ่ม "ตัวกรอง" ไม่ได้กรองลูกค้าจริง (แค่สลับ status = DELIVERED ซึ่งใช้กับออเดอร์)

### 1.4 การเงิน

- หน้า "รับเงิน" กับ "ประวัติเงินเข้าออก" อ่านจากตาราง `ledger` ที่เป็น**เครดิตทดลอง**ทั้งหมด ไม่ใช่เงินจริง
- ตาราง `payments` มีแล้ว (migration 004) แต่ยังไม่มีหน้าจอไหนแสดง
- คอลัมน์ "ยอดโอน" กับ "เข้ายอด" แสดงตัวเลขเดียวกัน ยังไม่มีค่าธรรมเนียมหรือยอดสุทธิ
- สถานะเขียนตายตัว ยอดบวกขึ้น "สำเร็จ" ยอดลบขึ้น "ชำระแล้ว"
- กรองตามช่วงวัน ประเภท หรือสถานะไม่ได้ และไม่มีสรุปยอดหรือดาวน์โหลด
- ไม่มีระบบคืนเงิน ปรับยอด หรือบันทึกการถอน
- **ยอดขายในแดชบอร์ดคิดไม่ตรงกัน**
  - เซิร์ฟเวอร์ (`adminOverview.revenue`) นับเฉพาะ `DELIVERED`
  - หน้าจอนับ `DELIVERED + PREORDER`

### 1.5 ออเดอร์

- มีตารางกับแท็บสถานะ และดาวน์โหลด CSV ได้
- ไม่มีหน้ารายละเอียดออเดอร์ จึงไม่เห็นว่าส่ง ID ตัวไหนไป จ่ายผ่านอะไร หรือจ่ายเมื่อไหร่
- คอลัมน์ "การชำระ" เดาจากสถานะออเดอร์ ไม่ได้อ่านจากตาราง `payments`
- ยกเลิก คืนเงิน หรือเปลี่ยนบัญชีที่ส่งให้ลูกค้า (กรณีบัญชีเสีย) ไม่ได้
- กรองตามวัน สินค้า หรือลูกค้าไม่ได้ และโหลดทุกออเดอร์พร้อมกันโดยไม่แบ่งหน้า
- คิวพรีออเดอร์ส่งของได้แล้ว (MIG-005) แต่ยังยกเลิกหรือคืนเงินคิวไม่ได้

### 1.6 สินค้าและสต็อก

- สินค้าใหม่ได้ตัวเลือกแค่ 1 ตัว ชื่อตายตัวว่า "โค้ดดิจิทัล"
  - เพิ่ม แก้ หรือลบตัวเลือก (เช่น 7 วัน / 30 วัน) จากหลังบ้านไม่ได้
  - แก้ราคาได้เฉพาะตัวเลือกที่ถูกที่สุด
- ตั้งสินค้าเป็นพรีออเดอร์จากหลังบ้านไม่ได้
- อัปโหลดรูปไม่ได้ (`art` เป็น "gift" ตายตัว) และลบหรือเก็บเข้าคลังไม่ได้
- รายการสินค้ามีแค่ค้นหาชื่อกับแท็บเปิดหรือปิด กรองตามหมวด สต็อก หรือประเภทไม่ได้
- **สต็อก** เติมได้ทั้งแบบคู่ ID/รหัสผ่าน และแบบโค้ดเดี่ยว แต่ยังขาด
  - หน้าดูรายการสต็อกของแต่ละตัวเลือก (แบบปิดบังรหัส)
  - การปิดหรือลบบัญชีที่เสีย
  - การนำเข้าเป็นไฟล์ CSV
  - การเตือนเมื่อสต็อกใกล้หมด

### 1.7 ระบบรวม

- `/api/admin` ส่งสินค้า ออเดอร์ ลูกค้า และ ledger **ทั้งหมด**ในคำขอเดียว ร้านจริงจะช้าลงเรื่อยๆ ต้องแบ่งหน้าที่เซิร์ฟเวอร์
- ระบบบันทึก `audit` ไว้แล้ว แต่ไม่มีหน้าให้ดู และไม่ได้เก็บค่าก่อนและหลังแก้
- เปลี่ยนรหัสผ่านแอดมินได้ทางเดียวคือ `wrangler secret` ยังไม่มีหน้าในหลังบ้าน
- **แอดมินยังเป็นแบรนด์ ASTRA** มีโลโก้ "A" ข้อความ "จัดการร้านค้าของคุณบน ASTRA" และชื่อ "ผู้ดูแล ASTRA"

## 2. Functional Requirements

กติกาที่ใช้กับทุกข้อ
- เงินเก็บเป็นสตางค์ (integer)
- เวลาเก็บเป็น UTC แต่แสดงเป็น Asia/Bangkok
- ทุกการแก้ไขโดยแอดมินต้องบันทึก audit (ใคร ทำอะไร กับอะไร เมื่อไหร่ ค่าก่อน ค่าหลัง เหตุผล)
- ทุกตารางในหลังบ้านต้องแบ่งหน้าและกรองที่เซิร์ฟเวอร์ ไม่ใช่โหลดทั้งหมดมากรองในเบราว์เซอร์

## 3. ลำดับงานที่แนะนำ

**รอบ 1 — งานใน SOW ที่ยังขาด**
- FR-M1, FR-M2, FR-M3 แชทและแจ้งเตือน
- FR-R1 อันดับผู้ซื้อ
- FR-O1 และ FR-S1 เอาเมนูเดโมออก
- FR-S7 เปลี่ยนแบรนด์หลังบ้าน

**รอบ 2 — โครงการเงินจริง**
- FR-F1, FR-F10 ประเภทรายการเงินและสูตรยอดขาย
- FR-F2, FR-F3, FR-F4, FR-F9 หน้ารายการเงิน ตัวกรอง สรุป CSV
- FR-O2, FR-O3, FR-O4 ตารางออเดอร์ ตัวกรอง หน้ารายละเอียด
- FR-S2 ตั้งค่ารับเงิน ทำเมื่อลูกค้าเลือกผู้ให้บริการแล้ว

**รอบ 3 — สินค้า**
- FR-P1, FR-P2, FR-P3 ตัวกรอง ตัวเลือก พรีออเดอร์
- FR-P7 หน้าสต็อก

**รอบ 4 — ลูกค้าและงานที่ต้องยืนยัน** (เริ่มเมื่อลูกค้ายืนยันขอบเขต)
- FR-C1 ถึง FR-C9 ลูกค้า
- FR-F6, FR-F7 คืนเงินและถอน
- FR-O5 เปลี่ยนบัญชีที่ส่งให้ลูกค้า
- FR-P4 รูปสินค้า
- FR-S3 ถึง FR-S5 บัญชีแอดมิน ทีมงาน audit log

## 4. คำถามที่มาร์คต้องถามลูกค้า

1. **ขอบเขต** — การจัดการลูกค้า (แก้ข้อมูล แบน รีเซ็ตรหัส) คืนเงิน ถอน และรูปสินค้า อยู่ในราคาเดิมหรือเป็นงานเพิ่ม
2. **"ถอน"** — หมายถึงร้านถอนเงินออก หรือลูกค้าถอนเครดิตเป็นเงินสด
3. **ระบบเครดิต** — จะให้ลูกค้าเติมเครดิตไว้ในเว็บหรือไม่ (ถ้าไม่ใช้ FR-C7 กับรายการ TOPUP ตัดออกได้)
4. **ผู้ให้บริการรับเงิน** — เลือกเจ้าไหน (กำหนดการทำ FR-F5, FR-F8, FR-S2)
5. **ข้อมูลลูกค้า** — ต้องการชื่อ นามสกุล และเบอร์โทรตอนสมัครหรือไม่
