## ความหมายของ Phase ในชุดนี้

รหัส TEAM-P0 ถึง TEAM-P2 เป็นแผนรวมทีม ไม่ใช่ Phase 0 ถึง 5 ของ NOTT Sprint 1 เดิม ซึ่งเอกสารเดิมรายงานว่าจบแล้ว งานชุดนี้ต่อจาก baseline ปัจจุบันและไม่ลบแผนเก่า

| Phase | เป้าหมาย | สิ่งที่ต้องส่ง | เงื่อนไขจบ |
| --- | --- | --- | --- |
| TEAM-P0 เตรียมโครงและตกลงงาน | ทุกคนเข้าใจ scope สถาปัตยกรรม API และ UI ตรงกัน | decision log, ownership, API contracts, ตัวอย่าง UI, CI และแผนข้อมูล | ผ่าน G0 ในไฟล์ตรวจรับก่อนเริ่มงานเสี่ยง |
| TEAM-P1 ร้านเดียวที่เชื่อมกันจริง | ลูกค้ากับแอดมินคนละเครื่องใช้ร้านเดียวกัน | auth/roles ร้านถาวร catalog cart checkout ออเดอร์ สต็อก และหลังบ้านเชื่อม API | ผ่าน G1 รวมซื้อ TEST ข้ามเครื่องและสิทธิ์ข้อมูล |
| TEAM-P2 ฟังก์ชันตาม scope และส่งมอบ | ชำระเงินหนึ่งวิธี คิว แชท notifications ranking reports พร้อมตรวจรับ | ฟังก์ชันเชื่อมจริง QA recovery คู่มือ source และ UAT | ผ่าน G2A สำหรับ sandbox; ผ่าน G2B เพิ่มจึงเปิดรับเงินจริงได้ |

หากลูกค้ายังไม่เลือก provider ให้ทำ G2A ด้วย sandbox ได้ แต่สถานะสุดท้ายต้องเป็น “พร้อม UAT ทดลอง ยังไม่เปิดรับเงินจริง” งานเปิดเงินจริง G2B ยังไม่ถือว่าเสร็จ

## ขอบเขตที่รวมและไม่รวม

รวมตาม kickoff และขอบเขตที่ให้มา: responsive UI สมาชิก สินค้า ตะกร้า checkout ออเดอร์/พรีออเดอร์/คิว แชทในเว็บ การแจ้งเตือนในเว็บ อันดับผู้ซื้อ รายงานวัน/สัปดาห์/เดือน หลังบ้านสินค้า/โค้ด/ผู้ใช้ จ่ายหนึ่งวิธี ส่งโค้ด และ source code

ไม่รวมอัตโนมัติ: multi-vendor/หลายร้านเชิงแพลตฟอร์ม เช่าไอดี OTP บอท LINE wallet เงินจริง LINE/SMS/email/push notification และ API ภายนอกหลายช่องทาง ระบบภาษี/บัญชีเต็มรูปแบบ คูปอง/สะสมแต้ม/สมาชิกแบบเสียเงิน และฟีเจอร์ใหม่ที่ไม่มีใน SOW ต้องแยก change request

ร้านถาวรหนึ่งร้านไม่ใช่ระบบ multi-vendor เมนู /stores อาจเหลือทางเข้าหลังบ้านของร้านเดียวได้ ไม่ต้องทำระบบสมัครร้าน/เก็บค่าสมาชิกเพิ่ม

Kickoff เดิมเสนอกรอบ 8–10 สัปดาห์สำหรับโครงการทั้งหมด ไม่ใช่คำรับรองว่าเหลืออีก 8–10 สัปดาห์จากวันนี้ ให้ audit งานที่มีแล้วใน TEAM-P0 ก่อนปรับวันส่งจริง

| ช่วงในกรอบเดิม | งานเน้น | คนหลัก |
| --- | --- | --- |
| W1 | TEAM-P0 และตรวจของเดิม | ทุกคน มาร์คประสาน |
| W2–3 | TEAM-P1 และ shared-shop end-to-end | น็อต แบงค์ มาร์ค |

| Staff เห็นโค้ดหรือข้อมูลคนอื่น | น็อต มาร์ค | role matrix และ negative tests ทั้ง API/CSV/รายงาน |
| ตัวเลขรายงานไม่ตรงเงิน | น็อต มาร์ค | เวลา/สถานะ/คืนยอดนิยามเดียวกัน ตรวจเทียบชุด fixture ที่คำนวณได้ |
| แชทกลายเป็นช่องสแปมหรือ XSS | น็อต แบงค์ มาร์ค | จำกัดขนาด/อัตรา ขอบสิทธิ์ แสดงข้อความปลอดภัย และกำหนด retention |
| backup มีฐานแต่ไม่มี key | น็อต มาร์ค | กู้ข้อมูลเข้ารหัสจาก backup + key ที่เก็บแยกจริง |
| key rotation ทำโค้ดเก่าอ่านไม่ได้ | น็อต | key version และแผน re-encryption; ห้ามสุ่มใหม่ทับของเดิม |
| animation ทำช้าหรืออ่านไม่ได้ | แบงค์ | reduced motion keyboard focus โหลดต่ำ และเทสมือถือจริง |
| รูป/ชื่อ/รีวิวจากต้นแบบติดมาด้วย | แบงค์ มาร์ค | ใช้สื่อที่ได้รับอนุญาต ลบ dummy text และไม่แสดงรีวิว/ยอดขายแต่งขึ้น |
| API/provider เกินโควตาหรือ token หมดอายุ | มาร์ค | เจ้าของค่าใช้จ่าย budget alert ตรวจหมดอายุ และสถานะ degraded |
| ลูกค้าร้องเรียนหลังส่งมอบ | มาร์ค | คู่มือ ช่องทาง support ผู้รับผิดชอบ และรายการ bug/change request แยกกัน |

## เงื่อนไขปิดงานและการรับรอง

ใช้ G0 G1 G2A G2B ใน 04-ACCEPTANCE เท่านั้น การผ่าน demo ไม่เท่ากับ production การเปิดเงินจริงต้องมีหลักฐาน provider verification และลูกค้าตรวจรับ ไม่ใช้ปุ่มยืนยันทดลองเป็นหลักฐานเงินเข้า

ก่อนส่งแต่ละ Task ให้ระบุ commit SHA URL ทดสอบ ผล tests สิ่งที่ยังไม่ทำ และผลกระทบข้อมูล ในการประชุมให้พูด Task ที่ติดและคนที่ช่วยปลดล็อก แทนการรายงานเปอร์เซ็นต์อย่างเดียว
